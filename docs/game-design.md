# Poketato 游戏设计：宝可梦搜打撤

这是一款新的宝可梦动作游戏，不是 [poke-rouge](https://github.com/DietCokewithSugar/poke-rouge) 的移植。玩法循环是进关卡搜索、实时战斗、把战利品带出去。死亡丢掉这一局里捡到的东西。

战斗和装备参照暗黑破坏神 2：白装、蓝装、黄装、绿装套装、暗金，前后缀随机，宝可梦可以穿装备。关卡结构参照 Minecraft Dungeons：一条主路、可选支路、精英房、宝箱房、Boss 门和出口，而不是随机一层层往下爬的肉鸽地牢。怪物是宝可梦，打死会掉装备。

画面是 2.5D：三维场景里站着会受光的精灵面片。工程用 Unity 6.3 LTS（6000.3.26f1）和 URP 17.3，要实时光、阴影和反光。联机是服务器权威；普通关卡最多 4 人。Boss 战、工会副本、世界战可以更多人，并且必须按角色、按技能记下输出。

## 1. 不做什么

上一版原型把 poke-rouge 的割草肉鸽搬进了 Unity：一波波刷怪、捡糖果升级、三选一卡牌、波次之间的商店。那一套停用。

本游戏没有这些东西：

- 没有波次生存，没有局内三选一，没有糖果，没有每波结束的随机商店。
- 技能和装备在城里配好再进本。本局不临时换构筑。
- 关卡是做好的任务图，房间种类和连通关系固定，只有刷怪位置、词缀和掉落用种子随机。
- 不把 poke-rouge、PokéRogue、PokéSurvivor 的代码或原图搬进仓库。PokéRogue 的代码是 AGPL，不能抄。

宝可梦名字、招式名和属性克制是玩法语言。精灵图和关卡原图的版权见第 13 节。不能再分发的素材不进仓库，用程序生成的占位。

## 2. 搜打撤循环

### 2.1 城里

玩家用一只宝可梦进本。城里可以做这些事：

- 选宝可梦、加点、把最多 4 个已学会的主动技放进快捷栏。基础攻击永远占一格，不占这 4 格。
- 从仓库穿上装备。武器、头盔、护甲、护手、鞋子、腰带、护符各 1 件，戒指 2 件。
- 用探险币买消耗品、修装备、洗点、扩仓库。不接真实货币。
- 组队，最多 4 人进普通关。Boss 战、工会副本、世界战用各自的人数上限。

天赋点 = min(等级, 30)。等级上限 40。31 级以后不再给天赋点，每级只加 2% 生命和伤害。

### 2.2 进本

一场任务就是一局。服务器用种子生成这一局的刷怪偏移和掉落。客户端不自己掷掉落。

背包分成两份：

- **入场装备**：从仓库穿进来的。死亡不删，但每件耐久降 15 点（上限 100）。耐久到 0 就坏掉，属性失效，回城修理前不能用。
- **本局掉落**：这一局里捡到的装备、本局金币、本局里买的消耗品。打上 `foundThisRun`。死亡时整包删除。如果本局掉落被穿在身上，死亡时从装备栏里拔掉，同样删除。

### 2.3 关卡里

玩家在房间之间走。战斗房、精英房、Boss 房要清完怪，门才开。起点、走廊、宝箱、商人、撤离点一开始就算通过。

房间种类：

| 种类 | 作用 |
|---|---|
| 起点 | 出生。附近通常有一条可选支路。 |
| 战斗 | 普通宝可梦。 |
| 精英 | 更少、更强，掉落更好。 |
| 宝箱 | 开一次，掉 2 件至少为魔法的装备。 |
| 谜题 | 拉杆或踏板。解开后打开旁边的隐藏房，不挡住主路。 |
| 商人 | 花本局金币。买到的东西算本局掉落。 |
| 隐藏 | 支路，主线通关不经过也行。 |
| Boss | 关底。清掉才打开主撤离点。 |
| 主撤离 | Boss 死后，站上去交互，把本局掉落锁进仓库。 |
| 提前撤离 | 支路上的出口。不用打 Boss 也能走，本局掉落保住，但没有通关奖金。 |

搜索就是走支路、开箱子、找隐藏房。不搜也能沿主路打到 Boss。

### 2.4 撤离和死亡

撤离是个人行为。人站在撤离点上交互，只结算自己的包。队友可以继续搜。

成功撤离：

- 本局掉落进入仓库，`foundThisRun` 清掉。
- 本局金币 1:1 变成探险币，再加通关奖金。主撤离拿全额奖金，提前撤离拿一半。
- 人离开这一局，不能再回来捡。

死亡：

- 本局背包、本局金币、身上穿的本局装备全部删除。
- 入场装备留在身上，耐久 −15。
- 输出统计保留，用来记这场 Boss 或大型战斗。
- 其他人还能继续。全员倒下则任务失败，没人能再撤离。

断线：服务器把角色留在原地 60 秒。超时按死亡处理，本局掉落删除。这一条由游戏服做，模拟核心只提供死亡结算。

## 4. 系别技能树

全游戏 15 棵树，一系一棵。火系只有一套，水系只有一套。喷火龙、风速狗、火伊布、火焰鸟点的是同一棵火树。双系可以把点数分到两棵树上。点数不互通：火树上花掉的点，不能拿来解锁飞行树的下一层。

结构参照魔兽世界经典天赋，不是巨龙时代的单选节点：

- 6 层，从 0 到 5。第 n 层要求这棵树里已经投入 5n 点。层 0 无门槛，层 1 要 5 点，层 2 要 10 点，层 3 要 15 点，层 4 要 20 点，层 5 要 25 点。
- 每层 3 个节点，从左到右读。最后一层只有中间的终极技。一共 16 个节点。
- 节点有等级。主动技大多 1 级。被动和基础攻击最高 5 级或 3 级。每升 1 级花 1 点。
- 前置是「学会」而不是「点满」。下面写了前置的，前置至少 1 级才能点。
- 点不够就点不满一棵树。单系 30 点可以在花掉 25 点后拿到终极技，还剩 4 点。双系如果对半拆，通常到不了层 4（门槛 20）。终极技要押注一系。
- 快捷栏最多 4 个主动技，外加永远可用的基础攻击。没手动配置时，自动带上已学会的、层数最高的 4 个主动技。

## 5. 实时战斗

模拟按固定步长跑，默认 20 步每秒（0.05 秒）。服务器一步一步算。客户端只发输入，不发伤害数字。

输入：移动方向、瞄准点、技能编号（0 是基础攻击，1 到 4 是快捷栏）、是否交互。

场景是平面上的 x / z。房间大约 16×12 米，房间之间有 4 米宽的门洞。人能过门，怪不出自己的房间。

### 5.1 属性换算

```
生命 = 种族生命 × 1.4 + 30 + 装备
攻击、防御、特攻、特防、速度 = 种族值 + 装备
护甲 = 防御 × 0.8 + 装备护甲
武器伤害 = 6 + 攻击 × 0.15 + 武器
移速 = 4.2 + 速度 × 0.025 米/秒
基础暴击 5%，暴击伤害 150%
```

等级系数 `1 + (等级 - 1) × 0.04`，乘在伤害上。31 级以后的额外 2% 生命和伤害另外乘。

### 5.2 伤害

物理（近战、冲锋）：

```
原始 = (武器伤害 + 招式威力) × 技能系数 × (1 + 攻击 / 100) × 等级系数
减免 = 护甲 / (护甲 + 12 × 攻击者等级)
伤害 = 原始 × (1 - 减免)
```

特殊（投射物、大部分爆发）：

```
原始 = (招式威力 + 特攻 × 0.25) × 技能系数 × (1 + 本系伤害加成) × 等级系数
抗性 = clamp(目标抗性 - 穿透, -0.20, 0.75)
伤害 = 原始 × (1 - 抗性)
```

然后再乘属性克制、暴击、印记、虚弱。破甲让护甲先乘 0.75。

招式威力：格子 0 是 8，格子 1 是 18，格子 3 是 14，格子 4 是 10，格子 6 是 26，格子 8 是 16，格子 9 是 34，格子 12 是 48，格子 15 是 70。
技能系数：基础攻击是 `1 + 0.15 × 等级`，其他主动默认 1。治疗量是 `12 + 特攻 × 0.2`。护盾是 `10 + 防御 × 0.15`。

命中默认会中。闪避装备以后再把命中压到 50% 到 98% 之间。测试和服务器回放可以打开「必中、不暴击」，用来对伤害数字。

### 5.3 属性克制

用初代克制表。双系把两段乘在一起。幽灵打超能按设计上的 2 倍，不用初代游戏里打超能变成 0 的那个漏洞。

免疫：电打地面、地面打飞行、一般打幽灵、幽灵打一般、格斗打幽灵，都是 0。

火打草、水打火、草打水、冰打龙，都是 2。火打水、水打草，是 0.5。没写在例外里的是 1。

### 5.4 掉血以外的状态

灼烧每秒造成一小段伤害，持续 4 秒。中毒更弱，持续 6 秒。冰冻 1 秒不能动。眩晕 0.6 秒不能动也不能放技能。麻痹期间每次行动有 30% 直接浪费。减速把移速乘 0.65。混乱让移动方向乱掉。

个人掉落：怪死的时候，每个活着的玩家各自掷一次，不抢尸体。Boss 至少掉 2 件，而且稀有度从黄装起算。

## 8. 输出统计

只对三种战斗做完整统计：Boss 战、工会副本、世界战。

普通关里，只有打在 Boss 身上和 Boss 打出来的数字要记。小怪清理不进这张表，避免存档被刷屏。时空之塔、公会地下、北方争霸整场都记，因为这三场本身就是那三种战斗。

每个角色、每个技能一条：

```json
{
  "encounterId": "uuid",
  "kind": "boss",
  "missionId": "temporal-tower",
  "seed": 1,
  "startedAt": "2026-10-18T00:00:00Z",
  "endedAt": "2026-10-18T00:20:00Z",
  "participants": [
    {
      "characterId": "uuid",
      "speciesId": 150,
      "name": "超梦",
      "skills": [
        {
          "skillId": "psychic-15",
          "move": "精神突进",
          "casts": 3,
          "hits": 3,
          "damage": 4200,
          "healing": 0
        }
      ],
      "damage": 4200,
      "healing": 800,
      "damageTaken": 1500
    }
  ]
}
```

`kind` 取 `boss`、`guild`、`world`。`skillId` 是 `系-格子`，例如 `fire-0` 是火花，`fire-15` 是青焰。基础攻击也占一条，不能并进「其他」。

治疗记在治疗者的技能上。持续伤害记在挂上异常的那一招上。印记加成算在打出那一下的技能上，不算在挂印记的技能上。

同一场的各技能伤害加起来等于该角色的 `damage`。这是验收条件。

结算时游戏服把这份报告交给 Supabase。排行榜读它，不读客户端自己报的数字。

## 9. 联机

普通任务 1 到 4 人。第 5 个人被拒绝。

| 模式 | 人数 | 任务 |
|---|---:|---|
| 普通搜打撤 | 4 | 雾林、海滩、蒸汽、雷鸣、流沙、暗夜、隐藏之地、训练空地 |
| Boss 战 | 8 | 时空之塔 |
| 工会副本 | 8 | 公会地下 |
| 世界战 | 20 | 北方争霸 |

权威在服务器。模拟就是仓库里那套按步进的 C#（`RunSession`）。游戏服和客户端用同一套规则，客户端可以预测移动，伤害、掉落、死亡、撤离以服务器为准。

WebGL 不能当服务器，也不能随便开 UDP。浏览器客户端用 WebSocket 连游戏服。消息用 JSON，以后可以换二进制，字段不变。

客户端发：

```json
{ "t": "input", "seq": 120, "move": [0, 1], "aim": [3.2, 8.1], "skill": 1, "interact": false }
```

服务器发快照：角色位置和生命、房间开关、新掉落的物品 id、撤离结果、输出增量。客户端不允许发「我造成了 500 伤害」。

游戏服部署在 Render，是一个单独的 Web Service，不是现在这个托管 `webgl/` 的静态站点。静态站点继续给网页客户端。持久化用 Supabase：账号、仓库、探险币、战队、成就、排行榜、输出报告。密钥不进仓库。

兴趣管理：普通关把整张任务图都同步，4 个人房间不多。世界战只同步玩家附近的争夺点和 Boss 房，减少 20 人的快照。

掉线 60 秒按死亡。Boss 和世界战中途允许同战队的人补位，补位的人没有本局已结算的包，输出从进场开始记。普通关不补位，避免把别人的搜刮进度稀释掉。

## 11. 画面

Unity 6000.3.26f1，URP 17.3。场景是三维的：房间用方块铺地面和墙，宝可梦是朝向相机的面片，只绕竖直轴转，保持站立。这就是 2.5D。

光照：

- 一盏方向光，软阴影，照全图。
- 每个房间一盏点光。熔岩房用暖色，暗夜山丘用冷色并且更暗。Boss 房的点光可以投射阴影。
- 反射探针覆盖整张关卡，实时、盒子投影，醒来渲染一次。光滑地面（金属度约 0.25，光滑度约 0.85）会吃到探针。
- 海滩洞窟和带水的房间再加一台平面反射相机。反射相机不渲染水面那一层，避免自己照自己。URP 没有现成的屏幕空间反射，水面不靠 SSR。

管线资源是 `URP_25D`：前向渲染、主光阴影、附加光阴影、软阴影、反射探针混合和盒子投影。原来的 2D 渲染器不再作为默认管线。

宝可梦没有可用的立绘时，按属性色生成一块带眼睛的占位图，点采样，挂在会裁切透明的 Lit 材质上，这样能投阴影也能受光。

操作：WASD 或方向键移动，鼠标瞄准，数字键 1–4 放技能，基础攻击自动在近处打出，F 或空格交互。T 开关自动战斗，方便没人坐在键盘前时看一场。自动战斗只是演示，规则和手操是同一套。

## 13. 存档约定

游戏服和 Supabase 用这些对象。模拟核心不连数据库。表名是约定，迁移脚本不在这一份设计里写进 `supabase/`。

- `profiles`：用户 id、显示名。
- `characters`：用户、图鉴编号、等级、经验、梦幻的变身系。
- `talent_ranks`：角色、`skillId`、等级。
- `items`：实例 id、主人、底材、稀有度、物品等级、耐久、词缀 JSON、暗金 id、套装 id、是否在仓库、穿在哪个槽。
- `wallets`：探险币、战队勋章。
- `guilds` / `guild_members`：战队和身份。
- `lockouts`：战队、`lockoutId`、完成时间。
- `encounter_reports`：第 8 节的 JSON。
- `achievements`：用户、成就 id、解锁时间。
- `leaderboard_entries`：榜 id、用户、分数、更新时间。由撤离和报告写入，不由客户端直接 update。

撤离时游戏服在一个事务里：把本局物品插入 `items`，加上货币，写排行榜，如果这场有报告就插入 `encounter_reports`。死亡不插入本局物品。

## 14. 工程里已经能跑的部分

设计是整款游戏。代码先做能无头跑起来的核心，不把商城支付、战队数据库和 WebSocket 服务器写进 Unity 的 `Backend` 目录。

核心在 `unity/Assets/Scripts/Extraction`：30 只、15 棵技能树、加点规则、实时战斗、掉落、死亡丢包、撤离、8 张主题关加训练关、Boss / 工会 / 世界战的人数上限和输出统计。Unity 场景用 URP 前向管线、方向光阴影、点光和反射探针把同一场模拟画出来。

商城商品、成就和排行榜的 id 在 `MetaCatalog`，和上面的表一致，方便存档那边对上。真正的 Supabase 和 Render 游戏服不在这份核心里改。
